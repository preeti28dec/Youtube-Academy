Section 1

Project kya hai

Yeh ek course bechne wali website hai. Sohail apna YouTube course online bechte hain — student website par aata hai, payment karta hai, aur turant course dekhna shuru kar deta hai. Beech mein kisi ko kuch manually karne ki zaroorat nahi padti.

Poora flow — ek line mein

Student site par aata hai› Payment karta hai› Account apne aap banta hai› Course unlock› Videos dekhta hai› Progress save hoti hai

Sabse khaas baat

Videos secure hain

Jisne paise nahi diye, woh video nahi dekh sakta — chahe usko link hi kyun na mil jaaye. Yeh is project ki sabse zaroori requirement thi, aur poora system isi ke aas-paas bana hai. Detail Section 6 mein hai.

Design kahan se aaya

Design ek prototype se liya gaya hai — wahi colors, wahi spacing, wahi text. Rang indigo (#4f56e3), font Inter, look saaf aur bharosemand — taaki site tez chale aur maintenance sasta rahe.

Database kyun PostgreSQL

Is site ka saara data aapas mein juda hua hai:

User ──< Order >── Course ──< Module ──< Lesson
  │                  │                      │
  └──< Enrollment ───┘                      │
  └──< Progress ──────────────────────────────┘
  1. Paisa involved hai. "Payment hua → account bana → access mila" — teeno ek saath hone chahiye, ya ek bhi nahi. Postgres transactions yeh guarantee dete hain.
  2. Duplicate rokna zaroori hai. Database khud double enrollment reject karta hai, chahe payment ka confirmation do baar aa jaaye.
  3. Reporting aasaan. "Is mahine kitne students" — ek query. Admin panel ke stats isi par chalte hain.
  4. Sasta aur aam. Har hosting provider deta hai, free tier mil jaata hai.

MySQL bhi chal jaata. MongoDB is project ke liye theek nahi — data relational hai, aur payments mein constraints ka database-level par hona zyada safe hai.

Section 5

Payment kaise kaam karta hai

Student details bharta hai› Gateway par payment› Gateway ka webhook› Account + access› Login details email par
Sabse zaroori baat

Course ka access browser ke "payment successful" message par nahi diya jaata. Woh message koi bhi nakli bana sakta hai. Access tab milta hai jab payment gateway ka server khud hamare server ko confirm karta hai (webhook), aur uska digital signature verify ho jaata hai.

Demo mode

Razorpay ki keys na hon to app "demo mode" mein chalta hai — poora flow waisa hi chalta hai (form, order, account banna, course khulna), bas asli paisa nahi katta. Keys daalte hi real ho jaata hai; code badalne ki zaroorat nahi.

Section 6

Videos kaise secure hain

Client ka sabse bada sawaal yahi tha: "kya koi doosra vyakti direct link se course videos dekh sakta hai?" Jawab: nahi. Teen layer lagi hui hain.

1
Video ka link page mein hota hi nahi

Page ka source code dekhne par video ki file ka pata nahi milta. Player har baar server se naya link maangta hai.

2
Server pehle check karta hai ki payment hua hai

Enrollment record hi access ka proof hai. Free preview lessons sabko milte hain, baaki sirf enrolled student ko.

3
Link sirf 2 minute chalta hai, aur sirf usi student ke liye

Link ke andar lesson, student aur expiry — teeno cryptographically signed hote hain. Link copy karke kisi aur ko bhejne par server saaf mana kar deta hai.

4
Har student ka watermark

Video ke upar student ka email halka sa dikhta rehta hai. Koi recording leak kare to pata chal jaata hai kisne ki.

Yeh test kiya gaya hai

TestResult
Apne account se video chalanaChalti hai
Wahi link kisi aur ko bhejna403 — nahi chalti
Wahi link dusre logged-in user se403 — nahi chalti
Purana (expire) link403 — nahi chalti
Link ko thoda badal kar try karna403 — nahi chalti
Video file ka URL seedha kholna404 — milti hi nahi
Video beech se aage khinchna (seek)Theek chalta hai
Imaandari se ek baat

Duniya ka koi bhi system mobile se screen recording ko 100% nahi rok sakta — Netflix aur Udemy bhi nahi. Lekin DRM kai devices par recording ko black screen kar deta hai, aur watermark se leak karne wala pehchana ja sakta hai. Isliye leak ka risk practically bahut kam ho jaata hai. Jo bhi "100% impossible" ka vaada kare, woh sach nahi bol raha.

Section 10

Admin panel — rozmarra ka kaam

Sohail ko developer ki zaroorat nahi padegi. /admin par login karke:

  • Naya module (chapter) add karna
  • Naya lesson add karna — title, duration, video
  • Lesson ka naam ya duration edit karna
  • Kisi lesson ko free preview banana (bina payment ke dikhega)
  • Module ya lesson delete karna
  • Students ki list dekhna — naam, mobile, email, kab join kiya, kitna progress
  • Naam/email/mobile se student search karna

Video kaise jodein

Video kisi secure video host (Bunny Stream, VdoCipher, ya S3) par upload karein aur uska link admin panel mein lesson ke video field mein paste kar dein. Bas itna hi — baaki security apne aap lag jaati hai.

Video host kyun zaroori hai

Website ka server badi video files rakhne ke liye nahi bana. Video host se video tez chalti hai, kam kharcha hota hai, aur DRM jaisi suraksha bhi milti hai.

Section 11

Apne computer par kaise chalayein

Developer ke liye. Ek baar setup, phir ek command:

# 1. code lein
git clone https://github.com/preeti28dec/Youtube-Academy.git
cd Youtube-Academy

# 2. packages install karein
npm install

# 3. settings file banayein
cp .env.example .env

# 4. database banayein + demo data daalein
npm run setup

# 5. chalayein -> http://localhost:3000
npm run dev

Local par database SQLite hai — ek file, koi server install nahi karna padta. Production par wahi code PostgreSQL par chalta hai; sirf ek line badalti hai.

Docker se bhi chal sakta hai

cp .env.docker.example .env.docker
npm run docker:up     # app + PostgreSQL, dono ek saath
